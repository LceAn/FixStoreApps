# 商店应用修复工具 · Store App Repair Kit

一键修复 Windows 商店应用（UWP / MSIX）**打不开、启动无反应、激活失败弹窗**的工具。

典型症状（事件日志 `Microsoft-Windows-AppModel-Runtime/Admin` 中出现）：

```text
0x80070057: 无法为程序包 xxx 创建进程，因为在配置运行时的过程中遇到错误
0x80070057: 无法为程序包 xxx 创建桌面 AppX 容器，因为在配置运行时的过程中遇到错误
```

## 下载安装

从 [Releases](https://github.com/LceAn/FixStoreApps/releases/latest) 下载 `FixStoreApps-vX.Y.Z.zip`，解压到**任意固定目录**（不要放临时目录），然后：

- **手动模式**：双击 `启动菜单.bat`，按需选「智能修复 / 全量重置 / 只看状态」
- **自动模式（推荐）**：双击 `StoreAppGuard.exe`，常驻后台自动修复（菜单 [5] 也可以启动）

不想用Release？直接克隆本仓库也行，所有脚本是免安装的。

## 功能

| 菜单 | 工具 | 说明 | 耗时 |
|---|---|---|---|
| [1] 智能修复 | `FixStoreApps.ps1` | 扫描最近 72 小时的激活故障记录 → 逐个**真实启动验证** → 只修确实坏的应用，按修复阶梯自动升级手段，修完自动验证 | 1-5 分钟 |
| [2] 全量重置 | `ResetStoreIndex.ps1` | 把当前用户全部商店应用从磁盘清单重新注册一遍（经典重置命令的可视化版本） | 3-8 分钟 |
| [3] 只看状态 | — | 只扫描故障记录并逐个实测当前状态，不做任何修改 | 1-3 分钟 |

双击 `启动菜单.bat`（或任意一个 `.bat`）即可，需要点一次 UAC「是」。

## 修复阶梯（智能修复内置）

对每个确认损坏的应用，依次尝试，每一步都用**真实启动 + 事件日志核对**验证，成功即停：

1. **重注册**：`Add-AppxPackage -DisableDevelopmentMode -Register <manifest>`（无损，秒级）
2. **重建数据目录**：把 `%LOCALAPPDATA%\Packages\<应用>` 改名（保留 `.bak` 备份）后重注册——很多「重注册也修不好」的案例病根在数据目录
3. **重置应用**：`Reset-AppxPackage`（等效于 设置 → 应用 → 高级选项 → 重置）
4. **卸载重装**：对已知应用自动走 winget 重装（含卡死检测、自动重启安装服务后重试）

对 ChatGPT/Perplexity/Terminal/截图工具/1Password/商店等常见应用内置了 winget 重装 ID。

## 环境防线（工具会自动检查并询问是否修复）

这三项都和「商店应用反复损坏」强相关，工具每次运行会检查：

- **存储感知自动清理**开着 → 曾出现清理进程误删 `%LOCALAPPDATA%` 应用数据
- **快速启动**开着 → 关机非干净状态，应用状态易残留脏数据
- **商店自动更新策略**未禁用 → 「更新即损坏」的直接源头（`HKLM\SOFTWARE\Policies\Microsoft\WindowsStore → AutoDownload=2`）

## 日志

每次运行的完整日志在脚本同目录 `logs\` 下：

- `repair-<时间>.log` —— 智能修复
- `reset-index-<时间>.log` —— 全量重置

应用旧数据目录改名保留为 `<包族名>.bak-<时间>`，确认无问题后可手动删除。

## 后台守护进程 StoreAppGuard（NEW）

不想每次手动点？`StoreAppGuard.exe` 常驻后台，**故障发生时自动修复**，并配有**主窗口界面**：

- **主窗口**：顶部状态灯（绿=监控中/橙=修复中）+「立即检查修复」「开机自启」；中部**应用状态表格**（**应用图标+友好名称**（如 ChatGPT/Microsoft Teams，取自包清单与系统仓库，悬停显示包族名）、状态/修复级别/上次修复/是否运行中）；下部**实时日志**（彩色高亮自动跟随）；底部状态栏统计
- **关窗不退出**：点窗口 X = 最小化到托盘继续守护（气泡提示一次）；双击托盘图标或运行 `StoreAppGuard.exe --show` 唤起主窗口；托盘右键「退出」才真正退出
- **应用列表右键菜单**：打开应用（Get-StartApps 精确 AUMID 启动）/ 立即重试修复（清冷静期从第 1 级重来）/ 在微软商店中搜索重装 / 复制包族名——「待人工处理」的应用右键即可直接操作
- **高清图标**：Shell 接口按 64px 提取 EXE 图标资源 + 双三次插值高质量缩放到 32px，行高加大避免挤压
- **实时监听** `AppModel-Runtime` 208/216 与 `TWinUI` 5973 激活失败事件；另周期巡检兜底
- **巡检间隔可调**：主窗口顶栏「巡检间隔」1-60 分钟即改即生效（`guard-settings.txt` 持久化），巡检窗口随间隔自适应防漏事件
- **自动修复阶梯**（同一应用复发时自动升级手段）：
  1. 重注册 → 2. 重建数据目录+重注册 → 3. 重置应用
  - 三级均无效 → 气泡通知人工重装，24 小时内不再自动尝试（防循环空转）
- **防误伤设计**：45 秒防抖聚合、单应用 15 分钟修复冷却、正在运行的应用视为健康直接跳过、框架包/已卸载残留自动排除
- **托盘图标**：绿勾=正常 / 橙色=修复中；右键菜单：**查看日志（内置彩色日志查看器）**、立即检查修复、打开日志目录、开机自启开关、退出
- **内置日志查看器**：彩色高亮（成功绿/错误红/警告橙/动作蓝）、按日期切换历史日志、每 3 秒自动跟随最新、一键复制全部——普通用户无需接触日志文件
- **权限**：全部为当前用户级操作（重注册/数据目录/Reset 均不需要管理员），无需 UAC
- **开机自启**：写入 `HKCU\...\Run`（首次部署默认开启，托盘菜单可关）

命令行用法：

```bat
StoreAppGuard.exe              # 常驻托盘模式
StoreAppGuard.exe --once --days 3   # 扫描最近3天并修复一轮后退出 (可用于计划任务)
StoreAppGuard.exe --logviewer        # 只打开独立日志查看器
StoreAppGuard.exe --show             # 唤起已运行实例的主窗口
```

日志：`logs\guard-YYYYMMDD.log`；升级状态：`guard-state.txt`。

构建：`StoreAppGuard\build.bat`（使用 Windows 自带 .NET Framework csc 编译，无需安装 SDK，产出单文件约 60KB 的 EXE）。

## 常见问题

**Q：全量重置显示一堆「失败」？**
失败的基本都是框架包（VCLibs、UI.Xaml 等）和无清单的暂存包，属正常现象，与你手动跑原命令的输出一致。

**Q：为什么我反复重注册总治标不治本？**
本机案例中，真正的病灶包括：应用数据目录损坏、包注册状态深度损坏（Reset 才有效）、WindowsApps 下包目录 ACL 异常触发系统「修复 ACL → 下次仍失败」死循环。单纯重注册只能覆盖第一种。智能修复的阶梯就是针对这些层次设计的。

**Q：修复后又坏了？**
多数与商店自动更新强相关——更新瞬间把包状态弄坏。用本工具的智能修复即可恢复；并建议让工具帮你关掉商店自动更新（环境防线）。
