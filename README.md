# 商店应用修复工具 · Store App Repair Kit

一键修复 Windows 商店应用（UWP / MSIX）**打不开、启动无反应、激活失败弹窗**的工具。

典型症状（事件日志 `Microsoft-Windows-AppModel-Runtime/Admin` 中出现）：

```text
0x80070057: 无法为程序包 xxx 创建进程，因为在配置运行时的过程中遇到错误
0x80070057: 无法为程序包 xxx 创建桌面 AppX 容器，因为在配置运行时的过程中遇到错误
```

## 功能

| 菜单 | 工具 | 说明 | 耗时 |
|---|---|---|---|
| [1] 智能修复 | `FixStoreApps.ps1` | 扫描最近 72 小时的激活故障记录 → 逐个**真实启动验证** → 只修确实坏的应用，按修复阶梯自动升级手段，修完自动验证 | 1-5 分钟 |
| [2] 全量重置 | `ResetStoreIndex.ps1` | 把当前用户全部商店应用从磁盘清单重新注册一遍（经典重置命令的可视化版本） | 3-8 分钟 |
| [3] 只看状态 | — | 只扫描故障记录并逐个实测当前状态，不做任何修改 | 1-3 分钟 |

双击 `启动菜单.bat`（或任意一个 `.bat`）即可，需要点一次 UAC「是」。

## 修复阶梯（智能修复内置）

对每个确认损坏的应用，依次尝试，每一步都用**真实启动 + 事件日志核对**验证，成功即停：

1. **重注册**：`Add-AppxPackage -DisableDevelopmentMode -Register <manifest>`（无损，秒级）
2. **重建数据目录**：把 `%LOCALAPPDATA%\Packages\<应用>` 改名（保留 `.bak` 备份）后重注册——很多「重注册也修不好」的案例病根在数据目录
3. **重置应用**：`Reset-AppxPackage`（等效于 设置 → 应用 → 高级选项 → 重置）
4. **卸载重装**：对已知应用自动走 winget 重装（含卡死检测、自动重启安装服务后重试）

对 ChatGPT/Perplexity/Terminal/截图工具/1Password/商店等常见应用内置了 winget 重装 ID。

## 环境防线（工具会自动检查并询问是否修复）

这三项都和「商店应用反复损坏」强相关，工具每次运行会检查：

- **存储感知自动清理**开着 → 曾出现清理进程误删 `%LOCALAPPDATA%` 应用数据
- **快速启动**开着 → 关机非干净状态，应用状态易残留脏数据
- **商店自动更新策略**未禁用 → 「更新即损坏」的直接源头（`HKLM\SOFTWARE\Policies\Microsoft\WindowsStore → AutoDownload=2`）

## 日志

每次运行的完整日志在脚本同目录 `logs\` 下：

- `repair-<时间>.log` —— 智能修复
- `reset-index-<时间>.log` —— 全量重置

应用旧数据目录改名保留为 `<包族名>.bak-<时间>`，确认无问题后可手动删除。

## 系统要求

- Windows 10 1809+ / Windows 11（`Reset-AppxPackage` 需要较新版本，没有则自动跳过该级）
- PowerShell 5.1+（系统自带），点一次 UAC

## 常见问题

**Q：全量重置显示一堆「失败」？**
失败的基本都是框架包（VCLibs、UI.Xaml 等）和无清单的暂存包，属正常现象，与你手动跑原命令的输出一致。

**Q：为什么我反复重注册总治标不治本？**
本机案例中，真正的病灶包括：应用数据目录损坏、包注册状态深度损坏（Reset 才有效）、WindowsApps 下包目录 ACL 异常触发系统「修复 ACL → 下次仍失败」死循环。单纯重注册只能覆盖第一种。智能修复的阶梯就是针对这些层次设计的。

**Q：修复后又坏了？**
多数与商店自动更新强相关——更新瞬间把包状态弄坏。用本工具的智能修复即可恢复；并建议让工具帮你关掉商店自动更新（环境防线）。
